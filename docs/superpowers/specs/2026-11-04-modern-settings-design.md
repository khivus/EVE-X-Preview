The human requested both a plan and implementation. Both editors expose every existing workflow; AHK retains the thumbnail/hotkey/monitoring engine, canonical settings model, validation, migrations and persistence. Keep configuration format and application versions unchanged. Following the later user authorization, commit and push the reviewed feature to S0CT/EVE-X-Preview-but-gayer on feature/avalonia-settings and open a PR against khivus/EVE-X-Preview dev. Do not publish releases or change the installed host application. Execute all application and test processes in Windows Sandbox. Source changes remain in this repository.

## Existing foundations

`SettingsSchema` describes scalar fields, sections, dependencies and choices. `SettingsModel` owns drafts, profile origins/inheritance, row operations, undo and changed-leaf merging. `SettingsTables` adapts tables to legacy storage. `SettingsWorkbench` currently owns atomic Apply and restart. Specialized workbench pages contain event, sound, profile/group, diagnostic and preview workflows. Extract shared operations rather than creating equivalent C# business logic. Baseline Sandbox tests: 345 passed, 3 legacy panel-layout failures; preserve that evidence and distinguish baseline failures from regressions.

## Architecture decisions

1. Export a versioned contract directly from AHK schema/table/default definitions. C# consumes metadata dynamically; no parallel list of ordinary fields. Specialized tables, groups, events, sound library and runtime commands have canonical AHK adapters and dedicated UI components. All mutations are validated by AHK. C# retains unfinished text for validation feedback and prevents Apply until pending edits are accepted.
2. Local RPC uses a hidden AHK message window and bounded `WM_COPYDATA` requests. Each request is JSON with `version:1`, a 32-hex `id`, `method`, `session`, and `arguments`. AHK writes a matching JSON response atomically to `%LOCALAPPDATA%\EVE-X-Preview\IPC\<installation-id>\<id>.json` before returning. Requests and responses have size limits; filenames come only from validated IDs; cleanup expires old responses. Validate the sender's window/process/user. No network listener or privileged service. Responses contain `version`, `id`, `ok`, and either `data` or `error:{code,message,details}`.
3. Installation ID is lowercase hex SHA256 of UTF-8 normalized, lowercase absolute installation directory without trailing slash. Window titles: `EVE-X-Preview.SettingsBridge/1/<id>/runtime` and `/offline`. This separates copies and source/compiled locations. The modern editor has a named per-user/installation single-instance gate and activation signal. Closing the editor releases its lease and exits.
4. The server owns a `SettingsModel` per editing lease. `hello` checks bridge/schema compatibility; `metadata` exports the contract; `begin` acquires the lease; `snapshot` reads it; mutations (`select-profile`, `set`, profile/group/inheritance/rows/event/sound commands, `undo`) update that model; `validate` returns issues/conflicts; `apply` uses canonical merge/save; `discard` resets it; `end` releases it. A snapshot includes `session`, `profile`, `profiles`, `dirty`, `values`, `canUndo`, `runtime`, and an opaque `draft` payload for restart/handoff recovery. The client treats draft contents as opaque. The metadata shape and exact method arguments are documented in `docs/settings-bridge.md` before independent UI/backend work.
5. Coordinate internal/external leases. Opening another editor while a dirty draft/dialog exists focuses the current editor and explains how to finish. Clean editors can be exchanged. Runtime exit, reload and profile activation must protect either editor's draft. Disconnects are bounded; retain the client draft and offer reconnect/recovery rather than silently discarding it.
6. Apply performs three-way conflict detection on changed settings before the existing changed-leaf merge. Unrelated runtime position/discovery/tray changes survive. Profile rename retains origins and concurrent runtime values. Shared Apply rolls back memory on save failure and retains the draft. After a successful runtime Apply, flush the RPC response then restart AHK; the existing C# process reconnects and keeps page/window/scroll state. Built-in resumes via its existing capture mechanism.
7. Direct external launch discovers a runtime first. If absent, start a short-lived canonical AHK settings host (`SettingsHost.ahk` in source, packaged `EVE-X-Preview-SettingsHost.exe`). It uses the same load/validate/migrate/save code and exposes no hotkeys/thumbnails. It terminates when the editor exits. If runtime starts meanwhile, transfer the opaque draft to the runtime and revalidate conflicts; never allow independent concurrent writes. Serialize canonical load/save with a per-installation mutex and advertise runtime startup before loading settings. Offline preview/runtime-only actions report unavailable clearly.
8. Global `SettingsEditor` preference values `automatic` (default), `modern`, `builtin` are exported in the shared schema and available in both editors. Open/default tray double-click respect it. Always expose `Open internal settings`. Probe the companion executable with a bounded `--probe <response-file>` invocation, check protocol/schema/name, and fall back on absence/incompatibility/failure. Log a discoverable reason without repeated modal dialogs. Paths use the script/application directory.
9. Avalonia Fluent themes honor system/light/dark. Use a grouped navigation rail, search, profile selector, readable setting cards, accessible keyboard focus, inline errors, typed choices/toggles/numbers/colors/fonts/folders/hotkeys, and a persistent draft/action bar. Dedicated row editors support add/delete/reorder/copy/paste/undo; events and sound assignments have real controls. No raw JSON editing as the shipped UI. Runtime previews/actions remain AHK-owned. Preserve any off-screen recovery behavior across all monitors.
10. Publish self-contained `win-x64` without trimming/AOT initially; package all native and runtime dependencies. Extend existing build tooling with an optional built-in-only package. Measure actual startup/working set/package bytes in the guest. Do not assert performance or live EVE compatibility from synthetic tests.
